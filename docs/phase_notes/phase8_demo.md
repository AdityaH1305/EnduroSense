## What was built

### The dashboard (`app/`)

Nothing is trained in the dashboard. It loads the saved calibrated models and the final results, and shows decisions for the unseen test batteries and flights.

| Page | What it shows |
|---|---|
| **Three missions, one battery** | One unseen battery before take-off and three recorded missions that the minutes-left rule approves. EnduroSense approves two and refuses the one that would have cut 5 Wh into the reserve |
| **Mission check** | Any unseen battery at any moment, against a planned mission (distance, payload, speed, altitude, wind) or a recorded one. Both ranges, P(success), each rule's decision, and what was measured afterwards |
| **Fleet** | The fleet simulation from the final evaluation, and a live rerun with other fleet sizes, workloads and thresholds |
| **Results** | The success criteria, both models' test results, the decision comparison, and what did not hold up |
| **How it works** | The method in plain language, with its limits |

- **Where the numbers come from.** The battery model's ranges are the ones saved by the final evaluation for every reading of the test batteries. The mission model runs live on whatever mission is entered. The dashboard's scores equal the final evaluation's exactly (a test compares all 2,550 take-off combinations).
- **The three-missions case is real and not hand-picked.** It is chosen by a fixed rule from the test data: the battery with the most missions that minutes-left approves and EnduroSense refuses, the refused mission with the median shortfall, and the smallest and largest approved missions.
- **It shows a failure too.** One of the prepared examples is a case EnduroSense gets wrong.
- **Structure:** `app/logic.py` holds everything the dashboard computes and contains no Streamlit code, so it is tested like any other module; `app/charts.py` builds the charts; `app/streamlit_app.py` is the pages.
- **Theme:** fixed to a light theme (`.streamlit/config.toml`), for projectors.

### The report and the slides (`docs/build/`)

Both are generated by scripts that read every number from the result files, so they cannot drift from the tables.

- **Report:** summary and success criteria, the idea, data, method, test results with five tables and four figures, what held up and what did not, limitations, reproducibility, the dashboard, next steps.
- **Slides:** 13 slides. The charts are redrawn at slide-readable sizes; the three-missions slide uses the same real case as the dashboard. Slide 11 is "What did not hold up".

## The test set was not reopened

Phase 8 added nothing under `src/` or `scripts/`. The code fingerprint still matches the last entry of the test access log. The builder scripts live in `docs/build/` and the dashboard in `app/` for that reason.

## Changes from the plan

- **Payload out and back** is offered as a mission type (delivery: out with the payload, back empty) and a single payload value, not two separate fields.
- **Battery ranges are read, not recomputed.** The plan implied running Model A inside the dashboard. The dashboard uses the ranges the final evaluation saved for the same model, which is faster and guarantees the demo shows exactly what was evaluated.
- **The "judge moment"** uses three recorded missions of different sizes, not the "short and calm / headwind / heavy payload" trio sketched in the plan, because the cases come from real test data chosen by a fixed rule.
- **Stretch goals not done:** a simulated high-wind stress test and timing on a Raspberry Pi. Both are listed as next steps.

## Limits

- **The slides need PowerPoint to rebuild** (the script drives the installed application). The `.pptx` itself opens anywhere.
- **Visual checks of the dashboard were partial.** The first two pages were inspected in a browser; all five pages, every prepared example, the reveal toggle, the threshold slider and the live fleet run are exercised headlessly by a test. A dry run on the presentation machine is still worth doing (`docs/demo_script.md`).
- **The dashboard shows test data.** That is deliberate (the evaluation is finished and nothing is tuned in the dashboard), but it means the examples are few: 11 batteries and 40 flights.
