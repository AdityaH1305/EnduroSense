# EnduroSense

**Uncertainty-aware mission feasibility prediction for UAVs.**

Instead of only predicting "minutes of flight left", EnduroSense predicts:

- **Model A: energy available.** The watt-hours the battery can still deliver before reaching a safe reserve, from battery telemetry.
- **Model B: energy required.** The watt-hours a planned mission (distance, speed, payload, altitude, wind, return leg) will use.

Both predictions come with calibrated uncertainty ranges. They are combined into **P(success)**, and a fleet scheduler approves a mission only if P(success) ≥ τ (default 95%).

The project plan is in [docs/EnduroSense_Project_Plan.docx](docs/EnduroSense_Project_Plan.docx), and the phase-by-phase build plan is in [docs/IMPLEMENTATION_PLAN.md](docs/IMPLEMENTATION_PLAN.md).

## Data

**CMU "Data Collected with Package Delivery Quadcopter Drone"** (Rodrigues et al., 2021). This is 209 flights of a DJI Matrice 100, with battery voltage and current, wind, GPS and IMU readings at about 8 Hz.

1. Download the dataset from <https://doi.org/10.1184/R1/12683453> (`12683453.zip`, about 250 MB).
2. Extract `flights.csv`, `parameters.csv` and `README.txt` into `data/raw/`.

The raw data is never modified. Every derived file is regenerated by the scripts.

## Setup

Requires Python 3.11.

```bash
pip install torch==2.7.1 --index-url https://download.pytorch.org/whl/cu118
pip install -r requirements.txt
pip install -e .
pytest
```

Tests marked `data` need the raw dataset and are skipped if it is missing.

## Usage

```bash
python scripts/01_profile_data.py   # Phase 0 dataset profile -> data/processed/flight_summary.csv
python scripts/02_prepare_data.py   # Phase 1 cleaned tables -> data/processed/{samples,flights,chains}.parquet
python scripts/03_make_split.py     # Phase 1 locked train/test split -> data/splits/split_v2.json (never overwritten)
python scripts/04_build_features.py # Phase 2 Model A labels/features + Model B leg & flight targets -> data/features/
python scripts/05_model_a.py        # Phase 3 Model A comparison (baselines + 5 algorithms, ~1 h, cached) -> results/model_a/
```

Test data is locked: `endurosense.data.split.select(df, "test")` raises unless `final=True`. It is only used in the final evaluation.

Further numbered scripts are added phase by phase. `scripts/run_all.py` will rebuild everything from the raw data.

## Layout

```
config.yaml          every tunable setting (reserve voltage, tau, seeds, splits, ...)
src/endurosense/     the Python package
  config.py          config loading, paths, seeding
  data/              loading, cleaning, phases, energy, wind, battery chains, split
  features/          Model A labels & causal features, Model B leg/flight targets
  mission.py         MissionSpec and phase-based mission energy assembly
  models/            baselines, tabular (Linear/RF/XGBoost) and sequence (LSTM/GRU) predictors
  evaluate.py        metrics, grouped CV, paired bootstrap comparison, latency/size
  plots.py           shared figure style
scripts/             numbered pipeline steps
tests/               unit and data-regression tests
docs/                plan, implementation plan, data report, chain review, literature, phase notes
config/              manual decisions (chain_overrides.yaml)
results/             generated tables and figures, per phase
data/                raw/ (not versioned), processed/, splits/
```
